### 설계 전략: 줄거리 기반 영화 추천 시스템

1. 데이터 준비
- 사용 데이터베이스: lg_hellovisionvod.vod_movie
- 사용 컬럼:
  - asset_id: 영화의 고유 ID.
  - asset_nm: 영화 제목.
  - smry: 영화의 줄거리 (벡터화의 기본 데이터).
  - director: 감독 이름 (영화 스타일 반영).
  - actr_disp: 주요 출연진 (사용자의 배우 선호도 반영).
  - genre: 영화 장르 (필터링 및 추천 가중치에 사용).
  - orgnl_cntry: 제작 국가 (지역별 추천에 활용 가능).
  - rlse_year: 영화 출시 연도 (최신 영화 선호도 반영).
  - rate: 연령 등급 (사용자 연령에 따라 필터링 가능).

2. 데이터 처리
- 텍스트 통합:
  - smry, director, actr_disp를 하나의 텍스트로 결합:
    "줄거리: {smry} 감독: {director} 출연진: {actr_disp}"
- 벡터화:
  - Sentence-BERT와 같은 NLP 모델을 활용하여 통합된 텍스트를 벡터화.
  - 결과 벡터는 768차원의 고정된 임베딩으로 저장.
- 데이터 정제:
  - director 및 actr_disp에서 불필요한 데이터(중복, NULL 값) 제거.
  - genre, orgnl_cntry를 표준화(예: "코미디" → "Comedy").

3. TMDB/IMDb 데이터 배제
- 배제 사유:
  - 현재 내부 데이터와 TMDB/IMDb 간 싱크를 맞추는 작업이 필요하나, 서로 다른 데이터 구조로 인해 매핑 작업이 복잡하고 시간이 소요됨.
  - 제한된 시간 내에 싱크 작업 완료가 어려워 현 단계에서는 적용하지 않음.
- 향후 개선:
  - 시간이 확보되면 TMDB/IMDb 데이터와의 매핑 및 통합을 통해 데이터 품질을 보강할 계획.

4. 추천 시스템 설계
- 유사도 계산:
  - 벡터 간 코사인 유사도를 사용하여 영화 간 유사성 점수 계산.
- 가중치 설정:
  - 추천 점수 계산 시 각 요소의 가중치를 설정:
    - 줄거리 유사도: 50%
    - 감독 유사도: 30%
    - 출연진 유사도: 20%
- 필터링:
  - 사용자가 장르(genre), 출시 연도(rlse_year), 연령 등급(rate) 등을 기준으로 추천을 필터링할 수 있도록 설계.

5. 데이터 저장
- 벡터 데이터베이스 구성:
  - 데이터베이스: Pinecone, ChromaDB 또는 Milvus와 같은 벡터 데이터베이스 사용.
  - 저장 필드:
    - asset_id: 고유 ID.
    - vector: 벡터화된 임베딩.
    - metadata:
      - asset_nm: 영화 제목.
      - genre: 영화 장르.
      - rlse_year: 영화 출시 연도.
      - director: 감독 이름.
      - actr_disp: 주요 출연진.
      - rate: 연령 등급.
- 쿼리 프로세스:
  - 입력된 영화 또는 사용자의 선호도를 벡터화하여 벡터 DB에서 가장 유사한 항목 반환.

6. 예상 문제점 및 대응 방안
- 문제: 데이터 누락 및 불완전성
  - 대응: 내부 데이터의 정제를 통해 품질 개선.
- 문제: 출연진 정보의 과도한 길이
  - 대응: 주요 출연진 상위 5명까지만 반영.
- 문제: 비정상적 추천 결과
  - 대응: 유사도 점수 외 장르, 출시 연도 등 추가 필터링 적용.

7. 사용자 경험(UX) 강화 방안
- 추천 필터 제공:
  - "감독 기반 추천", "출연진 기반 추천"과 같은 필터 옵션 제공.
- 유사 영화 목록:
  - 사용자에게 추천된 영화와 유사한 영화를 한눈에 볼 수 있는 UI 제공.
- 데이터 설명 추가:
  - 추천 이유를 간략히 설명(예: "이 영화는 줄거리와 감독 스타일이 비슷합니다.").
